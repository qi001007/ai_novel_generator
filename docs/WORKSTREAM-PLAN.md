## 一、已经能用的

**写一本长篇的主链**
- 四层规划都能在界面里直接改：A 全本蓝图、B 目录、C 剧情弧、D 单章简报；改完下一次生成就带上。
- 正文生成：按简报生成整章，边生成边显示，写完落库；生成时读了哪些资料全部列得出来。
- 机械校验：按简报里的「必要事实」逐字检查正文有没有写到，没通过会明说缺哪条。
- 审稿记录、AI 自检、通过终审、打回、事实落库：一条链都能点通，数据是真的。
- 章摘要、事实提取：有真数据，不是占位。

**资料与上下文**
- 全书只有一个资料池，对话和正文生成共用它 —— 不会出现「聊天时看到的和写正文时看到的不一样」。
- 上下文有预算（默认 12000 字），挤不下的那份会**明写在界面上**，不会悄悄丢。
- 注入清单按 A→B→C→D 排，**一份文件一行**，点开能看到这份文件每一节的原文（今天刚改的）。

**对话与 Agent**
- 对话可选模式（计划 / 写作）、能 @引用资料、能带附件 —— 附件真的进了模型输入
  （铁证：上传一个只存在于临时目录的文件，模型回答了里面唯一那句话）。
- Agent 能自己读文件、搜网页、多步推理，最后给「提案」，你点应用才写进文档。
  **它没有直接改你稿子的权力**，注册表里就没有写工具。
- 每条 AI 回复带可折叠的思考过程。

**界面**
- 书架：书卡右键 = 打开 / 更换封面 / 编辑信息（书名、简介、目标章数上限、文风约束）/
  删除（必须把书名原样打一遍才能删）。
- 设置：模型接入（多个供应商，正文生成、审稿、章摘要、对话各走哪家）+ 外观
  （主题三卡 + 强调色 / 代码配色 / 界面字号 / 正文字号 / 三种字体，含英文字体）。
- 深浅色 × 两色系 × 两代码配色 × 两档字号，全部真机量过对比度与点击命中区。

**可靠性（都是踩出来的坑换来的）**
- 数据库是唯一真源，文件栏里的 `.md` 是它的投影 —— **磁盘上没有这些文件**，
  它是给你读、给你改、也给你导出的一种通用格式（裁定见 `DECISIONS.md` D-26）。
  改这些文档**只有一条入口**。
- 正文与简报都有两面：渲染面用来看，源码面用来改，两面背后是同一份数据，不会各存一份。
- 全书与单章都能导出成**真的文件**（书架右键 / 文件树右键）：`.txt` 给发布平台粘贴，
  `.md` 给自己存档。没连起点这类平台之前，稿子至少能拿走。
- 删一本书会把它名下 14 张表的记录一起删干净，且不会碰到别的书（有测试钉住）。
- **删之前先复制一份现场**，设置 →「导出与恢复」里能看到删除记录并拿回来：
  整本书回到书架、单份文档回到书里原来的位置；书已经没了而只要一个文件时，
  会先问你要不要连书一起恢复，你说不要就把它写到导出目录。快照留最近 20 份。
- 人物删除按钮以前点了必然报错（端点根本不存在），今天补上了。
- 界面有一套「不许改回去」的自动断言（`frontend/src/uiInvariants.test.ts`）：
  改了界面不改断言，测试直接红。

## 六、对话 Agent 的工具面：现在真有什么、还差什么、我打算怎么加

你要的原文是「除了读写这种基本工具，也要具备联网功能，参考开源项目 / Codex 的 Computer Use /
插件或 MCP，把这些基本的都配上，可以先出一份计划」。这是那份计划。
**先说结论：读、联网、多步循环这三样已经在了，但联网只到「查维基百科」这一档，
差的不是数量而是质：抓不到网页正文、搜索源不可换、工具不能并行、跑完一步看不到花了多少。**

### 6.1 现在真有什么（代码里查出来的，不是照旧文档抄的）

| 能力 | 状态 | 证据 |
|---|---|---|
| 列文件 / 读文件 | **有** | `agent_tools.py` 的 `files()` 与 `read(path)`，读的就是那份投影，和你在界面上看到的同一份 |
| 联网查证 | **有，但只有一个源** | `search(query)` 打的是**中文维基百科**的 search API，取前 5 条标题+摘要（`SEARCH_RESULTS = 5`、超时 15 秒） |
| 多步循环 | **有** | `agent.py` 的 `DEFAULT_MAX_STEPS = 6`，到上限就停并说明「已执行：…」，不是无限烧钱 |
| 真 `tool_calls` 兼容 | **有** | 网关要肯给标准的 `tool_calls` 数组就照它走；不给才用我们自己那套标记（有些网关两个都不给） |
| 写文件 | **故意没有** | 注册表里没有写工具；它只能交「提案」，你点应用才落库。这条不是缺陷，是红线 |
| 抓某个网页的正文 | **没有** | 只有维基的摘要，打不开链接 |
| 搜索源可配置 | **没有** | 端点写死在代码里，不在「模型接入」那张供应商表里 |
| 一步里并行多个工具 | **没有** | 一步一个 |
| 每步的耗时/字节/失败原因上屏 | **一半** | 工具轨迹能折叠看到调了什么，但没有「这步花了多久、拿到多少字、为什么失败」 |

### 6.2 参考谁，各取哪一段

- **Codex / Claude 的 agent 循环**：学它的「预算 + 停止条件」，不学它的工具数量。
  我们现在只有步数上限，缺**字节与时间**两个闸——一轮把 20 个网页全文塞进上下文，
  比多走两步贵得多。
- **MCP（模型上下文协议）**：学它的**工具声明格式**（名字 + JSON Schema + 描述），
  这样以后加工具是往一张表里添一项，而不是改循环。
  **不引入 MCP 运行时**：那是给多进程/多机用的，本机单用户应用装它只多一份依赖和一条攻击面。
- **开源检索类 agent（Perplexity-style / storm 那一类）**：学它们的**两段式**——
  先搜到一批链接，再挑 2–3 个抓正文，最后带引用回答。今天缺的正是第二段。
- **Computer Use（操作屏幕）**：**不做**。这个应用没有需要点鼠标的第三方程序；
  把屏幕操作接进来只会带来不可复现的失败和真实的风险。

### 6.3 分五步，每步一条验收口径

1. **抓网页正文 `fetch_page(url)`** —— 只取正文（剥标签、限 8000 字）、只允许 http/https、
   带超时与重定向上限、结果进上下文**不进真源**。
   验收：问它「查一下徽墨的原料」，回答里能看到具体网页的正文片段而不是摘要。
2. **搜索源变成供应商** —— 在「模型接入」里加一类「搜索」：维基（默认，零配置）/
   Bing / Serper / Tavily（填 key 才启用），没 key 就老实说只能用维基。
   验收：换源之后同一个查询能列出不同来源；没配 key 时界面明写「当前只能查维基百科」。
3. **两段式检索 + 引用** —— 搜 → 挑 → 抓 → 答，答案下面列出用了哪几个链接
   （就是现在「引用 N 份资料」那一排，多一类「联网来源」）。
   验收：一条回答里能看到 2–3 个来源，点得到原文。
4. **预算从「步数」升级成「步数 + 字数 + 秒数」三个闸** —— 超任何一个都停下来交底，
   并把每一步的耗时与取回字数画进工具轨迹。
   验收：故意让它抓十个大页面，它在预算处停住并说明停在哪一步、已经花了多少。
5. **工具声明表化** —— 三个工具改成一张注册表（名字 / 参数 schema / 描述 / 是否只读），
   循环照表驱动。以后加 `list_arcs`、`find_name` 这类本地工具是添一行。
   验收：新加一个工具不改循环代码，且有测试钉住「表里没有写工具」。

**顺序的理由**：1、2 直接决定它联网查得准不准，先做；3 是把前两步串成有用的回答；
4 是防止 1–3 变贵；5 是收口，让后面加工具便宜。
一次会话做完一条，做完就交一条。

### 6.4 三条不动的边界

- Agent **没有直接改你稿子的权力**：注册表里永远不放写工具，改动一律走提案 → 你点应用 →
  那唯一一条写入口（D-01）。第 5 步的测试会把这条钉死。
- 联网拿回来的东西**只进这一轮上下文，不写进库**：不建网页缓存表、不做爬虫、不存历史抓取。
- 不引入 MCP 运行时、不做屏幕操作、不做后台常驻抓取。
