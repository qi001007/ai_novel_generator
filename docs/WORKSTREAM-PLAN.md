## 一、已经能用的

**写一本长篇的主链**
- 四层规划都能在界面里直接改：A 全本蓝图、B 目录、C 剧情弧、D 单章简报；改完下一次生成就带上。
- 正文生成：按简报生成整章，边生成边显示，写完落库；生成时读了哪些资料全部列得出来。
- 机械校验：按简报里的「必要事实」逐字检查正文有没有写到，没通过会明说缺哪条。
- 审稿记录、AI 自检、通过终审、打回、事实落库：一条链都能点通，数据是真的。
- 章摘要、事实提取：有真数据，不是占位。

**资料与上下文**
- 全书只有一个资料池，对话和正文生成共用它 —— 不会出现「聊天时看到的和写正文时看到的不一样」。
- 上下文有预算（默认 12000 字），挤不下的那份会**明写在界面上**，不会悄悄丢。
- 注入清单按 A→B→C→D 排，**一份文件一行**，点开能看到这份文件每一节的原文（今天刚改的）。

**对话与 Agent**
- 对话可选模式（计划 / 写作）、能 @引用资料、能带附件 —— 附件真的进了模型输入
  （铁证：上传一个只存在于临时目录的文件，模型回答了里面唯一那句话）。
- Agent 能自己读文件、搜网页、多步推理，最后给「提案」，你点应用才写进文档。
  **它没有直接改你稿子的权力**，注册表里就没有写工具。
- 每条 AI 回复带可折叠的思考过程。

**界面**
- 书架：书卡右键 = 打开 / 更换封面 / 编辑信息（书名、简介、目标章数上限、文风约束）/
  删除（必须把书名原样打一遍才能删）。
- 设置：模型接入（多个供应商，正文生成、审稿、章摘要、对话各走哪家）+ 外观
  （主题三卡 + 强调色 / 代码配色 / 界面字号 / 正文字号 / 三种字体，含英文字体）。
- 深浅色 × 两色系 × 两代码配色 × 两档字号，全部真机量过对比度与点击命中区。

**可靠性（都是踩出来的坑换来的）**
- 数据库是唯一真源，文件栏里的 `.md` 是它的投影 —— **磁盘上没有这些文件**，
  它是给你读、给你改、也给你导出的一种通用格式（裁定见 `DECISIONS.md` D-26）。
  改这些文档**只有一条入口**。
- 正文与简报都有两面：渲染面用来看，源码面用来改，两面背后是同一份数据，不会各存一份。
- 全书与单章都能导出成**真的文件**（书架右键 / 文件树右键）：`.txt` 给发布平台粘贴，
  `.md` 给自己存档。没连起点这类平台之前，稿子至少能拿走。
- 删一本书会把它名下 14 张表的记录一起删干净，且不会碰到别的书（有测试钉住）。
- **删之前先复制一份现场**，设置 →「导出与恢复」里能看到删除记录并拿回来：
  整本书回到书架、单份文档回到书里原来的位置；书已经没了而只要一个文件时，
  会先问你要不要连书一起恢复，你说不要就把它写到导出目录。快照留最近 20 份。
- 人物删除按钮以前点了必然报错（端点根本不存在），今天补上了。
- 章节：**序号由位置决定、章名由主人给**。删一章后面自动前移、在其后插入自动后移，章名跟着章走（五张带唯一约束的表 + 弧起止 + 伏笔三处 + 人物两处 + 设定来源章一起搬）；改名写的是 B 目录那一行，仍然只有那一条写通路。老数据的空洞没补（见 D-29 末段与 28.6b）。

## 六、对话 Agent：不再自研循环，站在成熟开源项目上（2026-09-06 重写）

这一节是主人要的「重新出一套计划」。**三句话结论**：

1. 上一版计划错在把「循环、预算、重试、工具协议」这些全行业通用的零件又自己写了一遍 ——
   那正是主人说「我要花很多时间跟 token 去 debug，没有必要」的那部分。
2. 新计划：**循环交给 Pydantic AI**（预算、重试、并发、**离线测试**都是现成的），
   我们只留两样买不到的东西：**这台网关的方言适配器**和**本产品的红线与工具定义**。
3. 旧的自研循环不推倒：迁移期两套并存、一个开关切回、跑同一套契约测试。
   换完之后，调循环这件事**不再花主人的 token**（假模型回放就能测）。

### 6.2 一条决定性约束：这台网关不说标准话

任何「换框架」的计划都必须先过这一关，否则换完立刻坏：

- `agent.py` 头部注释记录 2026-09-04 实测：网关回 `finish_reason: stop`、
  **没有 `tool_calls` 字段**，模型想调工具时把厂商私有 XML 塞进 `content`。
- 铁证在数据库里：上一轮按主人授权删掉的那条脏数据（`chat_message id=20`）原文就是
  内容是 `[TOOL_CALL] {tool => "read_file", args => { --path "settings/foreshadow.md" }}
  `[/TOOL_CALL]`：方括号里包一段 hashrocket 风格的伪代码，既不是 JSON、也不是 `tool_calls` 数组。
- 同一个模型在连续三轮里分别用过**三种写法**：我们自家的 tool 围栏（三个反引号开收）、
  厂商私有 XML、上面那种 hashrocket 块，
  所以解析必须三种都认 —— 那 161 行就是为这件事存在的，它不是「重复造轮子」。

**结论**：框架能替我写循环，替不了这台网关翻译方言。所以新计划的形状是
「**框架的循环 + 一个约 150 行的方言适配器**」，适配器直接复用现有那 161 行的解析。

### 6.3b 主人问的 piAgent（Pi）：查到的事实，以及为什么还是不用它

「piAgent」在中文生态里指的就是 **Pi**（GitHub MCP 查到的：仓库 `earendil-works/pi`，
旧名 `badlogic/pi-mono`，npm 包 `@earendil-works/pi-coding-agent`，README 标题
"Pi Agent Harness"）。下面每个数字都是刚才从 GitHub 读回来的，不是印象。

| 事实（2026-09-06 查） | Pi | Pydantic AI |
|---|---|---|
| 语言 | **TypeScript** | Python |
| star / fork | **102,260 / 12,760** | 19,746 / 2,656 |
| open issues | 158 | 824 |
| 创建 / 最后更新 | 2025-08-09 / 今天 | 2024-06-21 / 今天 |
| 许可 | MIT | MIT |
| 它自己是什么 | 交互式**编码 agent** CLI + TUI + session 分享；包分`pi-ai`（多供应商统一 API）、`pi-agent-core`（带工具调用与状态管理的运行时）、`pi-coding-agent`、`pi-tui` | 类型安全的 agent 框架，跑在你自己的进程里 |
| 权限模型 | README 原文：**"Pi does not include a built-in permission system for restricting filesystem, process, network, or credential access. By default, it runs with the permissions of the user and process that launched it."** 内置工具是 Read/Edit/Write/Bash | 工具由我注册，注册表里没有写工具就是没有 |

三条不用它的理由，按分量排：

1. **语言不匹配是决定性的**。后端是 Python（FastAPI + SQLModel），数据在同一个 SQLite 文件里。
   要用 Pi 只有两条路：起一个 Node 子进程当 agent 服务（多一个运行时、多一套部署、
   每轮对话跨一次进程边界），或者把对话这条链改写成 TS（那等于把「唯一写入口」D-01
   变成跨进程的第二条通路）。**这两条都比多一个 pip 依赖贵，而且 debug 成本正是主人要省的那个东西。**
2. **它的默认方向和我们相反**。它默认能写文件、能起进程，边界要你自己上容器或 micro-VM；
   我们的红线是「Agent 永远没有写工具」。用它得先把它最像样的一部分关掉。
3. **它是给人用的编码 agent，不是应用内嵌的库**。TUI、AGENTS.md、自扩展 CLI、session 分享
   对一个本地写作应用是负担，不是资产。

但它有一件事**我们抄**：它的供应链做法。README 写明直接依赖全部 pin 精确版本、
`.npmrc` 设 `min-release-age=2`（当天发布的依赖不许进锁文件）、锁文件当依赖事实源、
发布包带 `shrinkwrap` 固定传递依赖。这条写进 D-28 的边界，装 Pydantic AI 时照做。

社区规模它确实大 5 倍，这一点我不替自己遮：**如果主人愿意把对话 Agent 拆成独立 Node 服务**
（那是架构级决定，不是换库），Pi 是比 Pydantic AI 更强的产品，我可以按它重做这份计划。
不擅自做，是因为它改的是 D-01/D-02 那两条红线，不是改一个 import。

### 6.4 定了：Pydantic AI + 自写方言适配器。哪些交出去、哪些留下

**交出去**（框架承担，我不再维护）：步数 / 调用数 / token 预算、失败重试、
一次回复里多个工具调用的执行、工具参数校验（现在是手工把 `TypeError` 拼成中文提示）、调用追踪。

**必须留下**（本项目买不到，也不该买）：

| 留下什么 | 为什么 |
|---|---|
| 方言适配器（约 150 行） | §6.2：这台网关不给 `tool_calls`，翻译是我们独有的 |
| 三个只读工具的定义 | 读的就是那份投影，和主人在界面上看到的同一份数据（D-02 / D-15） |
| 提案协议（三个反引号 + `markdown` + 路径 那个围栏块） | Agent **没有写权力**，改动只能靠主人点应用（D-01） |
| 上下文构造 | 仍然只有 `collect_items()` 一个入口，**框架自带的 history / sessions 一概不用**（D-04） |
| 思考过程单独存列 | D-18 不变，适配器照旧把 `reasoning_content` 交出来 |

**可逆**：加一个配置项 `agent.engine`（`legacy` / `pydantic`），两条通路跑同一套契约测试；
`legacy` 保留到第 5 步才删。任何一步坏了，改一个值退回旧循环 —— 界面和数据都不动。

### 6.5 五步（每步一条验收口径 + 预计代价）

1. **接框架，不换行为** —— 装 `pydantic-ai-slim[openai]` 并 pin 版本；写 `GatewayChatModel`
   （包住现有 `OpenAICompatibleClient`，方言解析与 holdback 搬进去）；三个工具改成框架工具；
   `agent.engine` 开关落地。
   *验收*：① 同一份契约测试两个引擎都绿；② 用 `TestModel` 写一条「读文件 → 查网页 → 给提案」
   的三步剧本测试，**这条测试一次真 token 都不花**；③ 真机问一句需要读文件的话，界面上的
   思考、工具轨迹、引用与今天一致；④ 切回 `legacy` 一切照旧；
   ⑤ **适配器两条通道都要认**：非流式的 `message.tool_calls`（今天就有效）与
   **流式 `delta.tool_calls` 的分片拼装**（现在一个字都没读，见 `UI-BACKLOG 27.1`），
   并把网关在「带 `tools` 的流式请求」下的真实响应原样记进 `DECISIONS D-28`
   —— 「网关不给原生 tool_calls」这句话目前只在非流式那一路被观测过。
   *代价*：一次会话，真机验证 2–3 次调用。顺带把 §6.3 表里「并发执行」「usage 口径」
   两格从「文档说法」变成「本机实测」，并把 `pip show` 的依赖清单原样贴回本节。
2. **预算与用量交给框架** —— 删掉手写双闸，改 `UsageLimits`（`request_limit` +
   `total_tokens_limit` 并用，因为 `tool_calls_limit` 只数成功的）；每步耗时与取回字数进工具轨迹。
   *验收*：故意问一个要翻很多页的问题，它在闸口停住并说清停在哪一步、已经花了多少；
   界面能看到「第 2 步 · read_file arcs.md · 1.4s · 1.2k 字」；`generation_run` 里的
   token 数与今天同量纲（不许换个单位骗人）。
3. **联网补齐第二段 —— 抓正文是确定的，换搜索源要先重测**
   - 先做确定的那半：新增 `fetch_page(url)`，用 `trafilatura` 抽正文
     （剥标签、限 8000 字、只 http/https、超时与重定向上限）。维基那 5 条摘要终于能点进去了。
   - 再做不确定的那半，**先重测再承诺**：`ARCHITECTURE §4` 缺口 2 记着一条本机实测 ——
     DuckDuckGo 的 lite/html 两个端点回 **403**，「免密钥通用搜索」在这台机器上是**已知不通**的。
     所以 `ddgs` 只算候选，第 3 步第一件事是拿它发一次真请求：通了就用，
     不通就在本节改成「通用搜索只有填 key 的那条路（Serper / Tavily）」，
     界面上老实写「当前只能查维基百科」。**不承诺一个我没重测过的功能。**
   - 搜索源进「模型接入」当一类供应商（维基仍是零配置默认，和今天一样）。
   *验收*：问「查一下徽墨的原料」，回答里出现具体网页的**正文片段**与 2–3 个可点链接；
   免密钥搜索若重测仍 403，验收改成「配了 key 的那一家能出多源结果，没配就明写只能查维基」。
   联网内容只进这一轮上下文，**不入库**。
4. **一步多工具 + 按需开 MCP** —— 并发交给框架；将来真要接别人的 MCP server，
   用框架自带的 MCP 客户端开，**不装独立运行时、不做常驻进程**。
   *验收*：一句「对比第 1 章简报和第 3 弧的收束」在一轮里读到两份文件，轨迹里看得出它们并行。
5. **删旧循环** —— 新引擎在真机连续两周不出问题之后再动手，不提前。
   *验收*：`agent.py` 从 505 行降到 **< 150 行**（只剩适配器与注册表）；测试条数不降；
   `agent.engine` 与 legacy 分支一起删干净，不留半死代码。

预计：第 1、2、4、5 步各一次会话，第 3 步一到两次。
**总调试开销比上一版低，因为第 1 步之后循环可以离线测** —— 这一条就是主人这次要求的全部意义。

### 6.6 五条不动的边界

- Agent **永远没有写工具**：改动只能以提案出现，主人点应用才走那唯一一条写入口（D-01）。
  第 1 步就把它写成断言测试：注册表里出现任何非只读工具即红。
- **不拿框架的 sessions / memory 当第二份记忆**：历史仍从数据库读，上下文仍由
  `prepare_turn` + `collect_items()` 单构造器组装（D-02 / D-04）。这是换框架最大的隐性风险，先钉死。
- 联网结果只进本轮上下文：不建网页缓存表、不做爬虫、不存历史抓取。
- **不开任何外部遥测**（框架的 tracing / logfire 一律关）：本地应用不往第三方发调用细节。
- 不做屏幕操作（Computer Use）：这个应用没有需要点鼠标的第三方程序，接进来只会带来不可复现的失败。
