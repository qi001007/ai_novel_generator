## 1. 决定

### D-01 规划写入口只有文件投影一条

状态：生效。A/B/C/D 与文本设定只经 PUT /api/novels/{id}/files/{path} 写入；/planning/* 写路由只保留 410 退役桩。任何新规划能力必须复用该入口。

### D-02 SQLite 是唯一真源，Markdown 是投影

状态：生效。数据库存结构化列，Markdown 每次现渲染并解析回列。磁盘双向同步会引入冲突解决，v1 不做。

### D-03 正文与简报按章归组

状态：生效。规范路径为 chapters/NNNN/{draft.md,brief.md}；旧路径可读，新写只用规范路径，不做数据迁移。

### D-04 上下文只有一个资料池

状态：生效。collect_items() 是唯一采集入口；对话与写文只允许排序不同。新增资料改 collector，不在调用方拼提示词旁路。

### D-05 弧是存储，窗口是派生视图

状态：生效。剧情弧保留起止章与状态；生成时按目标章和预算计算窗口。不得用固定 1–30/31–60 文件或覆盖式 window.md 取代。

### D-06 注入清单必须可观察

状态：生效。终端调试与 generation_run.input_summary 使用同一清单，展示来源、字符数、档位、裁剪与原因。空块不能伪装成已注入。

### D-07 前端网络边界只在 api.ts

状态：生效。组件、页面与 store 不直接 fetch；离线演示如需 fixture，也实现同一 API 契约，不复制一套前端。

### D-08 编辑器采用 CodeMirror 6

状态：生效。TipTap 方案废止。编辑器扩展与文档结构识别围绕 CodeMirror 维护。

### D-09 D 层标题不重复章名

状态：生效。章名只归 B 目录；D 层标题只说明章号与“单章简报”，避免两个字段互相覆盖。

### D-10 文档结构锁定，AI 受字段白名单限制

状态：生效。小节标题、记录主键和文件章号不可任意改；actor=ai 只能修改明确字段且不能增删记录。结构变化必须走专用的人类动作。（「不能增」一半由 D-39 作废，本条其余部分继续生效。）

### D-11 AI 提案在展示 diff 前稳定化

状态：生效。未修改小节必须恢复为原文，防止模型重排整篇制造噪声；合法值修改仍由后端结构校验。

### D-12 v1 不做向量 RAG

状态：生效。只有出现可复现的“资料已采集但排序没给到”，且 SQL/规则排序无法解决时，才重开向量检索。

### D-13 “只允许末尾追加”已被 D-29 取代

状态：已废止。当前支持末尾追加、指定章后腾位和删除后顺延；全部章号引用必须由 renumber.py 一次搬齐。

### D-14 新建章节必须有显式入口

状态：生效。按钮、菜单或快捷键共享同一 action；不得以“点击最新章自动创建”代替。创建必须同时得到章节与简报。

### D-15 文本设定与人物档案并入文件投影写口

状态：生效。人物档案使用 settings/characters/{id}.md；头像是资产，走窄端点。世界观与伏笔使用各自文本投影。反馈分析保持专用流程，v1 不为它强开第二份可编辑投影。

### D-16 LLM 运行配置存数据库

状态：生效。app_config 是运行期真源，.env 只作首次种子与兜底；空值也覆盖兜底。密钥只写不读，连通测试不发计费 completion。

### D-17 2026-09-05 三项授权已关闭

状态：关闭。保留人物卡组件；推理单列由 D-18 管；历史控制块脏行已按备份后删除处理。此条不再承载新决定。

### D-18 推理与正文分列

状态：生效。chat_message.reasoning 不拼进 content，也不作为下一轮历史正文。对话流可单独展示 reasoning，其他 LLM 调用的流契约不因此改变。

### D-19 附件只属于本轮上下文

状态：生效。浏览器读取文本并作为 ContextItem 进入同一清单；不上传、不落盘、不进入下一轮。后端再次校验类型、数量和字符上限。

### D-20 供应商列表与任务路由分离

状态：生效。供应商保存连接信息，draft/review/summary/chat/image 路由选择供应商与模型；不为每个任务复制一套连接配置。

### D-21 外观偏好只存浏览器

状态：生效。主题、强调色、字体和字号属于这台机器，通过 appearance store 与 html data 属性单点写入，不进入 app_config。

### D-22 2026-09-06 六项授权已关闭

状态：关闭。对比度、顶栏按钮、删除语义、required_facts 机械口径、隔离 live 冒烟和生图槽位已分别落到实现或 D-23/D-24。此条不再充当进度表。

### D-23 删除采用事务内物理删除，删除前快照

状态：生效。作品删除显式清理 14 个作品子模型后删除 novel（共 15 张作品相关表），app_config 不参与。章节与人物删除验证归属；所有破坏性动作先快照。不做全库软删。

### D-24 无图片权限时生图保持未启用

状态：生效。当前配置的 key 只能调用 LLM/Embedding；图片请求曾返回 401。更换并验证有图片权限的供应商前，不展示可执行的生图假按钮。

### D-25 脚本调用 FastAPI 依赖时显式传 session

状态：生效。Depends 默认值只在 FastAPI 注入链有效；手动脚本必须自己建立并传入 Session。离线分支通过不能证明 live 分支有效。

### D-26 Markdown 是投影与导出格式，不是磁盘目录

状态：生效。它同时服务人类编辑、AI 提案、结构锁和可携带导出，因此保留；界面与文档不得把虚拟文件树描述为真实磁盘目录。

### D-27 简化删除确认后必须优先补恢复能力

状态：已完成并由 D-30 接管。确认不要求输入书名，但默认焦点在取消；删除前快照与恢复入口是这项简化的安全前提。

### D-28 Agent 循环迁移到 Pydantic AI

状态：进行中。循环、预算、参数校验与多工具执行交给 Pydantic AI；项目保留网关适配、只读工具、提案协议和产品边界。NOVEL_AGENT_ENGINE=pydantic 才启用新路，默认 legacy。切默认前补同参数去重、跑双引擎契约与真网关冒烟；验收后再删 legacy。

外部框架不得接管数据库历史、collect_items() 或外部遥测。直接依赖固定版本，传递依赖风险单独治理。

### D-29 章号是位置，章名属于 B 目录

状态：生效。插入后章号增加、删除后减少，章名随内容移动且只写 toc.md。所有带章号引用的表由 renumber.py 的集中清单搬移，禁止散落更新。

### D-30 快照记录范围，恢复一章是一个动作

状态：生效。快照 reason 必填；列表按真实时间排序并结合活库判断可执行动作。恢复一章一次带回简报、正文与目录行，且保留用户在快照后对其他章节的修改。

### D-31 有首条用户消息才算历史对话

状态：生效。历史列表由后端分组判定；空线程不显示，前端不乐观伪造第二套列表。

### D-32 章号压缩只能由主人确认触发

状态：生效。先展示逐行改号与弧范围报告，再快照，再按主人动作执行；禁止启动时自动迁移用户章号。

### D-33 UI 断言保护决定，不绑定源码位置

状态：生效。逻辑搬家时可修改断言的定位方式，但不能减少决定覆盖；必须用一次反向变异证明断言会在决定被破坏时失败。

### D-34 界面 kind/task 词表只有 labels.ts

状态：生效。A 层统一叫“全书蓝图”；组件不得各自维护 TASK_LABELS/KIND_LABELS 或时间格式化副本。

### D-35 投影语法表只有后端 _GRAMMAR

状态：生效。后端随 FileDoc 发布按 kind 的 grammar，前端据此识别结构和字段；测试 fixture 也从后端语法生成，禁止第二张人工标签表。

### D-36 写作上下文采用 B/C ±20 与“仅上一章全文”

状态：已决定，待实现。B 与 C 对目标章使用前后 20 章窗口；B 只带摘要字段。上一章简报和完整正文为必给，其他章正文禁止进入。世界观不整体升为必给，只有明确引用项优先；依据是现有 12000 字预算在长篇规模下已接近上限。

### D-37 Agent 通过确认动作卡触发现有生成链

状态：已决定，待实现。Agent 只定位目标章并形成动作卡；主人确认后由应用调用现有章节流式生成端点。不给 Agent 任意文件写工具，不另开规划写口；取消、刷新和重复点击必须幂等。

### D-38 确认后的首次 B/C 提案可初始化空投影

状态：生效。`actor=ai` 只表示主人已在提案卡上点击应用，不表示 Agent 获得自主写权限。空的 `toc.md` 或 `arcs.md` 没有可保护的主键，因此首次确认允许创建记录；非空文件曾按 D-10 一并拒绝增删与改号，「拒绝增」一半由 D-39 作废。这样保留单一 PUT 写入口，也避免把初次规划错误地当成 AI 结构篡改。

### D-39 AI 提案可追加记录，主键由系统分配（推翻 D-10 的「不能增」）

状态：生效。2026-09-09 主人在批次 35 裁定：「我在对话框里输入，这个对话 Agent 就能实现我人工操作的所有功能」，并选定口径「允许新增，且自动建章节本体」。据此：

- **可增**：`actor=ai` 的提案可追加记录。C 层用 `## 弧 ? 标题` 表示主键待分配，由文件层分配 `max+1`；B 层用文件里没有的 `## 第 N 章`。D-10「不能增删记录」里的**「不能增」一半作废**，「不能删」一半继续生效。
- **不可删、不可改号**：删除既有条目、改动已有主键仍按 D-10 拒绝。B 层的「删 5 加 6」就是改号，必然命中删除分支。
- **B 层新增即建章节本体**：`_write_toc` 追加新章号时同时建 `Chapter`（`brief_id` 允许为空），使左侧树与人工新建一致；建 `TocEntry` 的**两条**分支（已有条目的 `actor=ai` 追加、空目录或人类的全量写）共用同一次 `_ensure_chapter`，35.13 才把这条裁定落全。`_write_brief` 仍是另一处建本体，两处都在唯一 PUT 写入口内，不开第二条通路（D-01 不变）。
- **承诺必须实现**：写入层三处（`_resolve_ids` 的 surrogate 分支与两条 `_*_writer`）与提示词的「`?` 由系统分配」文案曾各写各的，实现却在零处。本条之后以写入层的真实分配为准，文案不许再许诺代码做不到的事。
- **判定只有一处**：主键配对由 `_resolve_ids` 一个函数裁定，预览（`chat.extract_proposals`）、提案工具闸门（`proposal_actions._gate`）、写入层三条 `_*_writer` 共用。闸门必须拿到当前文件（`documents.current_text_reader`），否则它会发出一张预览必拒、按下去什么都不发生的卡。
- **改号在成卡之前还原**：`stabilize_proposal` 按当前文件把主键写回去，所以「第 42 章改成第 99 章」产出的是一张**不改主键**的卡；写入层对原始文本仍然 422。还原发生在提案侧，不在文件侧开后门。

### D-40 五类规划只有一条提案通道

状态：生效。批次 35.8 裁定：A 蓝图 / B 目录 / C 剧情弧 / D 简报 / 新建人物**只能走各自的 `propose_` 动作工具**；手写整份文件的代码块只留给没有类型动作的对象（伏笔、世界观、改已有人物卡）。提示词里不许再出现「用工具还是手写都可以」这类等价表述。

- **依据**：那句等价表述就是第二条通道。作品 6 的真实流量里模型一次都没调用过 `propose_*`，全部手写并自造字段名（起止章 / 背景事件 / 悬念钩子），四张卡三张红。2026-09-10 同一份 C 层请求在装好写法表后重放，trace 是 `read_file(arcs.md)` → `propose_arcs` ×4，模型开始照抄文件里的 `arc: 4` 主键。
- **写法表与校验同源**：`markdown_doc.grammar_text(kind)` 与前端用的 `grammar_for_kind` 读同一张 `_GRAMMAR`（D-35），由 `agent_tools.read` 附在文件正文之后；提示词不抄字段名，抄一份就会漏改一份。

## 4. 仍值得保留的技术教训

| 编号 | 教训 |

| T-07 | 只读投影占位不得写进 metadata，否则假行会变成真行 |
| T-08 | 提案刷新后必须由后端真源重建，不能只活在前端组件状态 |

| T-15 | 网关流式原生 tool_calls 曾被客户端丢弃；适配层必须同时兼容原生与文本方言 |
| T-16 | 看似控制块的未知文本不得上屏或落库；重复工具调用要去重 |
| T-17 | 提案卡的预校验必须与最终写手同源，不能让必然 422 的提案显示可应用 |
| T-18 | 用 novel_id 与 chapter_id 拼请求前必须证明二者归属相同 |
| T-19 | CSS 语义类会被全局选择器污染；浮层和颜色只能靠真机截图发现 |
| T-20 | React 不保证把 style 从对象改为 undefined 时清掉自定义属性；空态写明确值 |
| T-21 | 固定数量和行号会漂移；需要数字时当场测，不从交接摘要继承 |
