## 1. 当前决定

### D-01 同仓纯净重建

在同一仓库建设新核心；旧数据库与媒体只备份，不迁移。合格前端和后端代码可选择性复用，不为旧服务建立新的兼容层。

### D-02 数据库与 Markdown

数据库是记录、关系、状态和版本的唯一真源；Markdown 是编辑、导入与导出形态。新系统使用独立数据库文件。

### D-03 单事务命令目录

页面、Agent 和 Workflow 共享一套函数 Schema 与处理器。写操作由应用用例拥有一次事务，并统一处理权限、风险、幂等、revision、差异和撤销。

### D-04 Agent 边界

只保留 Pydantic AI 模型工具循环。Agent 不使用 Computer Use 操作平台；低风险命令可执行并撤销，高风险命令必须暂停并等待确认。工作台中栏与启动页入口共用 AgentRun/ToolCall 审计，流式显示不能绕过持久化记录。

### D-05 Workflow 边界

Workflow 专精小说生产，位于工作台侧栏。React Flow 图是作者编辑执行定义的唯一视图，整图坐标与连线不暴露为可编辑 JSON，也不提供 Workflow 缩略图。发布后形成不可变版本；提示词模板可进入完整编辑器，未完成的节点不得提前出现在节点库。

### D-06 动态上下文

上下文由任务类型、结构距离、显式提及、审批状态、相关性和预算动态选择；卷窗口不是持久化上下限。首期不使用向量 RAG，只有可复现召回失败后才重新评估。

### D-07 研究资料与事实

网络资料保存标题、URL、抓取时间、摘要和可信度标记，默认不可信。只有用户确认的 Fact 可进入稳定上下文。

### D-08 地图参考边界

地图采用坐标化图块与相邻边缘条件扩图，参考 `stablediffusion-infinity` 的交互和融合思路，不直接搬运其旧界面和模型实现。结果先预览，确认后才进入正式地图。

### D-09 产品形态

当前优先完成网页端核心；未来网站增加账户、配额、PostgreSQL 与对象存储，桌面端优先用 Tauri 外壳和 Python Sidecar 复用同一前端。

### D-10 验收口径

自动测试、HTTP 可达、生产构建和真实浏览器验收是不同证据。第一次“重建完成”必须贯通 PRD 的完整创作与审计链路，任何付费 API 请求先单独获批。

### D-11 书架状态入口

书架当前只展示“最近”。置顶与归档字段可以保留为未来数据兼容，但没有置顶顺序、取消置顶、归档容器、恢复入口及系列关系之前，不展示相应筛选入口，不用半套前端状态冒充完整功能。

### D-12 编辑界面活动边界

编辑界面先定义滚动、缩放、分栏和越界语义，再实现视觉。滚动条与视口滑块采用悬停／聚焦／拖动显现且无两端按钮；鼠标滚轮必须可操作对应区域。正文 Minimap 是与真实正文视口同步的可滚动缩小视图；Workflow 不使用 Minimap，其画布、策略区和源码区必须有明确限位与全屏或滚动退路。

### D-13 前端尺度唯一真源

字体、间距、控件高度、圆角、边界和拖拽命中区采用“原始阶梯 → 语义 → 组件”三层 CSS token。新增控件只能消费语义或组件 token，不能在局部规则里重新决定同类尺度；视觉边界与可交互命中区允许分离。

### D-14 Workflow 用途与节点准入

Workflow 的 `purpose` 创建后固定为 `generation` 或 `review`，作品对每种用途最多绑定一个当前流程。首版只准入开始、动态上下文、提示词模板、模型调用、条件判断和输出六类经过执行测试的节点；每图必须且只能有一个动态上下文节点。Python、人工审批、循环和通用平台函数等到出现真实场景并完成端到端验证后再重新立项。

### D-15 审查、终审与导出

正文生成只产生候选，接受动作才写入工作稿；AI 自检只返回结构化问题，不直接改文。终审创建不可变 approved Revision；后续编辑让工作版本回到 draft，但保留最近有效终审快照。撤回会使该快照失效，默认导出只读取有效终审版本并明确列出缺章，禁止静默遗漏。

### D-16 短时通知

普通成功 Toast 显示 4 秒，普通错误 Toast 显示 8 秒，二者均可手动关闭。字段校验留在字段旁直到修正；只有完整诊断页面允许持续展示错误，不把一次连接成功或短时错误永久钉在业务页面。

### D-17 基础地图库边界

M-02 采用 `MapProject` + 不可变 `MapTile` 版本：单图存为 `(x=0, y=0, revision)`，每次生成只新增 draft 版本，确认该版本才把它设为当前版本并把上一确认版标为 superseded；`active_revision` 由已确认 tile 推导，并同步到工程设置供列表与预览读取。生成返回的是 24 小时供应商 URL，必须立即下载到数据库同级 `map_assets/<novel_id>/<project_id>/r<revision>.<ext>`，详情只读本机文件，不信任远端地址长期可用。生图前必须 `confirm_billing=true`，没有可用生图模型时在计费前拒绝；生成调用不自动重试，只有图片下载允许 3 次尝试且失败不落版本。图片下载使用 `trust_env=False` 并显式读取代理变量，因为本机 `NO_PROXY` 含 `[::1]` 会让 httpx 0.27 在请求前崩溃，回环地址保持直连。真实出图仍受 V-08 约束；分块扩图由 D-18 定义。

### D-18 分块扩图必须逐像素无缝

M-01 沿用 M-02 的不可变版本与确认链路，不新增表：每次扩图/单格重绘都生成一张覆盖整幅画布的 draft revision，元数据记录 `width/height/cols/rows/cell=1024`、操作与父版本；只有确认才替换当前正式地图。

无缝的做法是**遮罩编辑 + 遮罩外硬拼接**，不是羽化、模糊或缩放：底图按父版本放到确定偏移，白色遮罩只覆盖新增/重绘区域；供应商返回同尺寸图片后，遮罩外像素从父版本逐像素贴回，尺寸不一致直接 502，绝不缩放兜底。单块画布上限 4×4（4096 px，供应商输入上限）；非 1024 对齐画布不提供扩图入口并说明原因。

扩图是独立任务槽 `image_edit`（`llm.model.image_edit` / `llm.route.image_edit`），默认 `wanx2.1-imageedit`；未单独选择时跟随生图路由。提交是唯一计费动作，只发一次；轮询与下载可重试，失败不自动重发。调用前必须展示费用确认。

### D-19 供应商统一列表是投影，不做数据迁移

设置页把默认供应商与其他供应商画成同一张列表、同一套字段与动作，但存储格式不变：默认行仍写 `llm.api_base_url / llm.api_key / llm.timeout / llm.provider`，其余仍写 `llm.providers` JSON，读取时由 `resolve_routing()` 合成 `default` 行。理由：旧安装无需迁移即可得到统一管理面，也不会因为迁移让密钥换键位；`PUT /api/config/llm` 的语义（空密钥保留原值、null 数字不改动）继续由后端拥有。默认行名称固定“默认”且不提供改名，因为后端没有默认名称字段——宁可不给控件，也不做点了不生效的假控件。删除非默认行只改前端任务路由并回默认，保存时仍由后端校验。

### D-20 画布快捷键以视图为作用域

Workflow 画布的 Delete / Ctrl+C / Ctrl+V / Ctrl+Z / Ctrl+Shift+Z 以“画布视图仍在当前页面”为作用域，不以 DOM 焦点为界：删除节点后被聚焦的节点会卸载、焦点落到 `<body>`，若把 body 视为画布之外，紧接着的 Ctrl+Z 就会失效。守卫只排除输入框、文本域与 `contenteditable`，其余按键在画布视图挂载期间交给画布处理。

多选使用拖框选择：画布启用了 `selectionOnDrag`，Shift/Ctrl+单击不会累加选择，测试与验收都按真实手势框选。非法连线的原因用节点旁非模态气泡提示（`role="alert"`、4 秒自动消失），非法边不进入草稿也不产生撤销步——错误提示是反馈，不是文档状态。

### D-21 种子默认流程的占位只在未发布时成立

播种的 `系统 · 正文生成` / `系统 · AI 自检` 在**尚无 `WorkflowVersion`** 时只是占位：第一个真实用途流程可以接管该用途的绑定，否则生成与自检会一直指向无法运行的图。一旦种子流程已有发布版本，它就是可运行的当前默认，普通 `workflow.create`（`is_default=false`）不得改绑，也不得递增它的 `revision`。

判定必须同时看「系统命名」与「无发布版本」：只看名称前缀会把已发布种子误当占位（2026-10-23 真机复现：新建 review 流程后 review 绑定从 7 被改到 8，种子 7 revision 1→2）；只看是否发布会把用户刚创建、尚未发布的自建流程误当占位（同日后端回归：第二条自建流程顶掉第一条的 revision，重命名随后 409）。两条都要，不能简化成任一条。

### D-22 配置状态按任务实际路由判定

`configured` 的语义是「所有已经写进名称的任务，都能在它实际路由到的供应商上运行」：该供应商必须有 Base URL、自己的密钥、以及该任务的模型名。默认供应商的密钥不得替另一个供应商作证；没有模型名的任务不参与判定，因此只配置正文与审稿的旧安装仍算已配置。`/api/config/llm`、`/api/llm/status` 与设置页保存条共用这一判定；任务已命名但路由供应商缺密钥时，保存条显示「有任务缺少密钥」，不得显示「已配置」或「待选择模型」。

理由：2026-10-21 把文本任务切到未填密钥的百炼标准供应商后，旧的 `settings.is_configured` 仍只看默认供应商，于是底部与两个接口都误报可用——这正是「不把已有默认密钥跨供应商复用」的反例。2026-10-23 隔离库真机复现并修复。

### D-23 窄视口先保正文列，自动收起不落盘

三栏布局在窗口变窄时以正文编辑列为优先：`fitHiddenAt` 先收起对话栏，正文仍低于 `EDITOR_USABLE = 320` 时再收起结构栏；编辑器永不自动收起。自动收起只作用于当前视口，不写入 `localStorage`，窗口变宽时按同一 320px 判据逐级恢复；用户手动隐藏的栏不被自动重新打开。自动适配只在挂载与 resize 时执行，不接管拖拽。

理由：正文是工作台唯一不可替代的工作面，对话与结构可随时重开。旧实现让对话栏保持存储宽度、只让正文列吃 `1fr`，821px 时正文只剩 160px、620px 只剩 24px。把手动隐藏持久化会让一次窄窗访问永久改变桌面布局；把自动适配挂在每次渲染上会在拖拽中抢走宽度。2026-10-23 真机实测：821px 正文 476px、620px 正文 576px，工具栏高度均为 33px。

### D-24 C 层滑窗按章距筛、按弧数封顶

C 层候选先按章距窗口筛选：弧的 `[start_chapter, end_chapter]` 与 `[chapter - before, chapter + after]` 有交集才保留；`arc_window` 是**注入弧数量上限**，不是章距，候选按「当前弧 → 离本章更近 → 起点更早」排序后截断。即使 `arc_window` 放得很宽，章距窗口仍先挡住远弧。已开始的当前弧进必注入档，已结束的上一批弧进连续性档；尚未开始的未来弧标签追加「（未来）」并至少进附近档，预算收紧时不得先于最低档资料被裁掉。

理由：`arc_window` 此前只被保存、从未参与选择，调小也没有任何效果；未来弧因没有专属档位掉进最低档，预算紧时最先消失。2026-10-23 用 4 条各 12 章的弧实测：前=1、后=2、总窗=12 时，第 12 章注入 {弧1, 弧2}、第 14 章 {弧2}、第 24 章 {弧2, 弧3}、第 26 章 {弧3}、第 36 章 {弧3, 弧4}、第 38 章 {弧4}，且第 12 章的弧2 带「未来」。20 条单章弧在前=10、后=10、总窗=12 时只保留最近的弧4–弧15，证明封顶生效。
