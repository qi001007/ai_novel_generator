## 1. 当前决定

### D-01 同仓纯净重建

在同一仓库建设新核心；旧数据库与媒体只备份，不迁移。合格前端和后端代码可选择性复用，不为旧服务建立新的兼容层。

### D-02 数据库与 Markdown

数据库是记录、关系、状态和版本的唯一真源；Markdown 是编辑、导入与导出形态。新系统使用独立数据库文件。

### D-03 单事务命令目录

页面、Agent 和 Workflow 共享一套函数 Schema 与处理器。写操作由应用用例拥有一次事务，并统一处理权限、风险、幂等、revision、差异和撤销。

### D-04 Agent 边界

只保留 Pydantic AI 模型工具循环。Agent 不使用 Computer Use 操作平台；低风险命令可执行并撤销，高风险命令必须暂停并等待确认。工作台中栏与启动页入口共用 AgentRun/ToolCall 审计，流式显示不能绕过持久化记录。

### D-05 Workflow 边界

Workflow 专精小说生产，位于工作台侧栏。React Flow 图是作者编辑执行定义的唯一视图，整图坐标与连线不暴露为可编辑 JSON，也不提供 Workflow 缩略图。发布后形成不可变版本；提示词模板可进入完整编辑器，未完成的节点不得提前出现在节点库。

### D-06 动态上下文

上下文由任务类型、结构距离、显式提及、审批状态、相关性和预算动态选择；卷窗口不是持久化上下限。首期不使用向量 RAG，只有可复现召回失败后才重新评估。

### D-07 研究资料与事实

网络资料保存标题、URL、抓取时间、摘要和可信度标记，默认不可信。只有用户确认的 Fact 可进入稳定上下文。

### D-08 地图参考边界

地图采用坐标化图块与相邻边缘条件扩图，参考 `stablediffusion-infinity` 的交互和融合思路，不直接搬运其旧界面和模型实现。结果先预览，确认后才进入正式地图。

### D-09 产品形态

当前优先完成网页端核心；未来网站增加账户、配额、PostgreSQL 与对象存储，桌面端优先用 Tauri 外壳和 Python Sidecar 复用同一前端。

### D-10 验收口径

自动测试、HTTP 可达、生产构建和真实浏览器验收是不同证据。第一次“重建完成”必须贯通 PRD 的完整创作与审计链路，任何付费 API 请求先单独获批。

### D-11 书架状态入口

书架当前只展示“最近”。置顶与归档字段可以保留为未来数据兼容，但没有置顶顺序、取消置顶、归档容器、恢复入口及系列关系之前，不展示相应筛选入口，不用半套前端状态冒充完整功能。

### D-12 编辑界面活动边界

编辑界面先定义滚动、缩放、分栏和越界语义，再实现视觉。滚动条与视口滑块采用悬停／聚焦／拖动显现且无两端按钮；鼠标滚轮必须可操作对应区域。正文 Minimap 是与真实正文视口同步的可滚动缩小视图；Workflow 不使用 Minimap，其画布、策略区和源码区必须有明确限位与全屏或滚动退路。

### D-13 前端尺度唯一真源

字体、间距、控件高度、圆角、边界和拖拽命中区采用“原始阶梯 → 语义 → 组件”三层 CSS token。新增控件只能消费语义或组件 token，不能在局部规则里重新决定同类尺度；视觉边界与可交互命中区允许分离。

### D-14 Workflow 用途与节点准入

Workflow 的 `purpose` 创建后固定为 `generation` 或 `review`，作品对每种用途最多绑定一个当前流程。首版只准入开始、动态上下文、提示词模板、模型调用、条件判断和输出六类经过执行测试的节点；每图必须且只能有一个动态上下文节点。Python、人工审批、循环和通用平台函数等到出现真实场景并完成端到端验证后再重新立项。

### D-15 审查、终审与导出

正文生成只产生候选，接受动作才写入工作稿；AI 自检只返回结构化问题，不直接改文。终审创建不可变 approved Revision；后续编辑让工作版本回到 draft，但保留最近有效终审快照。撤回会使该快照失效，默认导出只读取有效终审版本并明确列出缺章，禁止静默遗漏。

### D-16 短时通知

普通成功 Toast 显示 4 秒，普通错误 Toast 显示 8 秒，二者均可手动关闭。字段校验留在字段旁直到修正；只有完整诊断页面允许持续展示错误，不把一次连接成功或短时错误永久钉在业务页面。
