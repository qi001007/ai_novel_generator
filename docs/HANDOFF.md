### 主人只做一轮约 20 分钟真实试用

此时间是操作目标，不是已完成实测。先由开发侧建好隔离测试作品、两条当前且已发布的基础流程和必要写作资料；主人只判断搜索/剧情/文字质量。真实调用前另行确认模型、请求上限、输出上限和费用，Agent 一条消息可能包含多次模型调用，不以「点一次」计算预算。

1. **讨论（约 4 分钟）**：发送「我想写一个送信人发现自己送的是死者记忆的故事。给我三种冲突，并指出各自容易俗套的地方。只讨论，不保存设定。」合格：三种路线有实际区别，回答承接追问，作品资产没有静默新增。
2. **资料（约 4 分钟）**：发送「查中国古代驿站如何换马、谁能使用，给出处；区分查到的事实与可以改编的虚构。资料不足就说明。」合格：工具轨迹确实调用搜索；至少两个可点开的来源支持具体事实，不能把搜索摘要冒充已读网页全文。
3. **正文（约 6 分钟）**：由开发侧给两章补齐蓝图、目录、覆盖剧情弧和章节简报，用基础正文流程分别生成短候选，第二章承接第一章的一条明确线索。检查是否遵守视角、人物和禁改设定；点击接受后只写一次，再对其中一章执行 AI 自检并查看实际问题与运行详情。两章试用只用于发现明显问题，不能据此承诺长篇稳定性；不要用「生成按钮无报错」判断文学质量。
4. **恢复（约 3 分钟）**：刷新页面、切换另一测试作品再返回，检查正文、标签、对话和两类运行记录；重启由开发侧代做。
5. **笔记（栏目实现后约 3 分钟）**：摘录一段讨论，修改标题/正文，刷新后找回；确认它未自动进入正式设定。该步当前待实现，不能按现有界面勾通过。

出现正文被无提示覆盖、跨作品串内容、重复写入、伪造搜索来源或失败却报成功时立即停止该链路；只记录触发动作、预期、实际和截图/运行 ID，开发侧复现后修复，不要求主人重复盲测。

### Workflow 怎么搭

首次先用作品自带的两条系统流程：左侧 Workflow → 选择「正文生成」或「AI 自检」→ 核对模型节点供应商/模型 → 保存 → 发布 → 确认左树显示「当前」及版本号。生成与自检各有独立当前绑定；自检的输出格式必须为「结构化自检问题」。更换供应商后，应修改草稿并重新发布，再验收当前版本。

基础链：开始 → 动态上下文 → 提示词模板 → 模型调用 → 输出。提示词模板保留 `{{input}}` 承接上游；否则可能把已选资料从下游提示词里丢掉。

只做一次有意义的改链试验：在隔离测试作品复制正文流程，通过「添加节点」增加提示词模板和模型节点，把链改为「开始 → 动态上下文 → 提纲提示词 → 提纲模型 → 正文提示词 → 正文模型 → 输出」。正文提示词要求依据 `{{input}}` 中的提纲写正文；删除旧直连，输出只接最终正文模型。保存/发布后在调用记录确认两个模型都执行，第二个输入包含第一个结果。会增加一次模型调用，真实测试前需计入预算。

当前仅开放开始、动态上下文、提示词模板、模型调用、条件判断、输出六种节点；「添加节点」可添加现有类型的实例，不能自动创造新能力。新增节点类型需要同时扩展后端契约、校验和执行器、前端类型与属性面板、版本兼容及行为验收。循环、任意 Python、通用平台函数和图像参考不在本轮可用承诺内；不要让主人为了验收先手搭这些节点。

### 建站的最小顺序（目标：自用与少量受邀用户）

1. 冻结首版范围：正文/自检、对话、创作笔记；其余新节点和地图高级能力独立排期。
2. 准备私有预发布环境：复用现有前端，后端由进程管理器或容器运行，前面加 HTTPS 与身份网关；后端端口不直接暴露公网。先不开放注册。
3. 选择并验证数据隔离方式：少量受邀用户可以先使用每人独立实例/数据库/媒体目录并由网关按身份授权；共享多用户实例则必须先实现用户归属、全路由权限检查和相应数据库迁移。前者是缩小首版的候选方案，尚未部署。两种方式都必须证明用户甲不能读写用户乙的正文、对话、运行、媒体、导出、备份和配置，不能只把登录页挡在前面。
4. 配置服务器专用模型凭证及服务端并发/用量上限；密钥不进入前端包或公共日志，普通用户不可读取他人的供应商配置。
5. 数据库与媒体作为一致备份单元，备份加密并异机保留；在空环境恢复一部测试作品，核对正文、对话、流程版本、运行详情和图片。上线前保存迁移前备份与上一版本镜像/代码，并做一次升级失败后的回滚演练；保留结构化运行错误、请求 ID、耗时与用量，默认不记密钥或整段私密正文。
6. 身份与隔离反例、备份恢复、重启、费用限制验收通过后，再绑定域名邀请第一批用户。服务器、域名、运营预算待部署阶段确定；当前本地 API 不属于可直接公网发布的版本。
