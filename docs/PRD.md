# 小说工作台产品需求

版本：纯净重建基线（2026-10-19）

本文是当前产品需求真源。完成状态看 `WORKSTREAM-PLAN.md`，技术边界看 `ARCHITECTURE.md`，视觉与交互细则看 `UI-DESIGN.md`，决定与废止项看 `DECISIONS.md`。

## 1. 产品定位与原则

这是面向长篇小说创作的本地优先工作台。它解决的不是“一次生成一章”，而是长期写作中的上下文失忆、设定漂移、人物失控、伏笔断裂、流程不可复现和人工核对成本。

- 作者拥有最终写入权；AI 可以讨论、检索、生成和调用受约束的平台函数，不能静默覆盖高风险内容。
- 作品结构、资料库、正文、对话、Workflow、审稿和生成记录共同服务一条创作闭环，不形成数据孤岛。
- 数据库是唯一持久化真源；Markdown 是编辑、导入和导出形态。
- 页面按钮、对话 Agent 与 Workflow 节点调用同一套函数目录，不维护三份业务实现。
- 上下文必须可预览、可解释、受预算约束；选中和未选中的资料都能说明原因。
- 先完成能持续写作和审计的核心闭环，再扩展账户、配额、云端和桌面封装。

## 2. 核心界面

### 2.1 作品启动页

- 页面采用 Codex 项目启动器的信息层级，同时沿用原工作台的克制配色、立体书封和紧凑控件。
- 顶部只保留产品名称、居中的作品搜索和设置等必要入口；同一“新建作品”主动作不得重复出现。
- 最近一次打开或写作的作品成为“继续写作”主卡；打开另一作品后，主卡必须随真实状态更新，不能绑定固定作品。
- 下方紧凑列表展示全部未归档作品的小封面、标题、当前卷章、字数、最近编辑时间和状态。
- “最近”按真实最近使用时间排序。置顶与归档只有在排序、取消置顶、归档容器、恢复入口及系列关系均有完整数据语义后才展示。
- 新建作品向导只收集必要信息，其余内容由 Agent 在工作台内引导完成。

### 2.2 三栏工作台

- 左侧是 VSCode 式 Activity Bar 与资源导航，固定提供：文章结构、设定库、人物库、世界库、地图库、Workflow、对话记录。
- 中间始终是 Copilot 对话区，用于讨论写作方向、搜索资料、规划内容和调用平台函数。
- 右侧按当前对象显示 Markdown 编辑器、正文、人物卡、世界条目、Workflow 画布、地图或审批差异。
- 三栏支持拖拽、隐藏和恢复；同一拖拽手势中能越过关闭阈值并反向恢复，重载后恢复每部作品自己的状态。
- 编辑区使用 VSCode 式 Minimap 表达和控制滚动位置；原生纵向滚动条隐藏，不能在 Minimap 旁再出现第二条滚动轨道。
- 顶栏提供作品切换、最近作品和返回启动页。切换作品时保存并隔离栏宽、隐藏栏目、当前文件、标签页、编辑缓冲和对话。

## 3. 作品、结构与文档

### 3.1 作品与树形结构

- 支持新建、打开、切换和删除作品。
- `OutlineNode` 组织卷、章节和阶段结构；支持显式追加、插入、排序和删除。
- 删除、批量替换和结构重排属于高风险操作，必须先预览真实差异并经用户确认。
- 每部作品独立持有结构、文档、资料、对话、Workflow、地图和运行记录，禁止跨作品泄漏编辑缓冲或上下文。

### 3.2 分层写作资料

- 文章主链路层：全书核心目标、主题、主要冲突、约束和长期推进方向。
- 目录层：卷、章节、阶段及其全局定位。
- 卷层规划：每卷目标、阶段冲突、关键转折和收束。
- 章节规划层：每章事件、人物目标、冲突、视角、事实和承接关系。
- 正文与自定义 Markdown：作者直接编辑、渲染、导入和导出。
- 所有可编辑资产具有 `revision`、`draft/approved/retired` 状态、来源、更新时间、版本记录和撤销入口。

### 3.3 知识库与稳定事实

- 人物以卡片管理；主角、重要配角和最近出现角色具有不同召回优先级与可见范围。
- 世界库保存规则、组织、地点、约束和关键事实，避免不同章节随意改写基础设定。
- 研究资料保存标题、URL、抓取时间、摘要与可信度，默认不可信。
- 只有用户审批为 `approved` 的 `Fact` 才能进入稳定上下文；草稿与网络资料只能作为临时或研究上下文。

### 3.4 创作笔记（待实施，R-04）

- 在工作台左侧提供独立的「创作笔记」栏目，按作品保存临时灵感、剧情推演、候选设定和自由 Markdown；列表支持标题/正文搜索，右侧沿用现有编辑器。
- 首版只做新建、编辑、从选中对话摘录、搜索、按需引用、确认后转设定和归档；不建设第二套知识库、无限画布或复杂笔记目录。
- 对话摘录同时保存原文快照、会话/消息引用和时间；用户可改写笔记，原始出处仍可追溯，删除原对话不会清空已保存摘录。
- 主人明确要求「记下来」时，Agent 可通过统一低风险命令保存笔记草稿；Agent 自行建议的笔记先预览再保存，普通讨论不自动写入。
- 笔记默认不注入稳定设定或每次模型上下文；用户可选中笔记作为本次参考，运行记录说明实际注入内容。相互矛盾的灵感可共存，不被当成已确认事实。
- 「转为设定」先展示目标位置及差异，经用户选择后走已有设定/事实审批入口，保留来源笔记，重试不得重复创建。
- 首版验收：手写、对话摘录、Agent 明确指令保存各一条；刷新与重启后内容/来源可读；两部作品互不串联；未选择的笔记不注入；转设定仅在确认后发生。当前仅有新核心 `document.update(kind=note)` 存储基础，栏目及完整交互尚未实现。

## 4. 对话 Agent

### 4.1 职责

- 与作者讨论写什么、采用什么结构、如何安排卷章和角色推进。
- 搜索和整理网络资料，保留来源并明确不可信内容。
- 读取当前作品、编辑器打开对象和分层资料，检查主线、人物、世界与章节规划的一致性。
- 通过受约束的后端函数创建、读取、修改和整理平台内部对象，使页面通过事件实时更新。
- 调用章节生成、审查、导入导出和 Workflow 等平台能力。

### 4.2 操作边界

- Agent 使用真实后端函数，不使用 Computer Use 操作平台内部能力。
- 保留 `pydantic-ai-slim` 作为唯一模型工具循环，不再并行维护旧自研 Agent 循环。
- 普通读取立即执行；创建草稿、修改未审批内容等低风险写入可以直接执行并可撤销。
- 删除、批量替换、重排结构、覆盖正文和修改已审批事实必须暂停，展示真实差异并等待确认。
- 所有命令进入 `Operation`，所有工具调用进入 `ToolCall`；保存执行者、参数、影响对象、差异、结果、失败和撤销数据。
- Agent 的可操作能力原则上覆盖人在页面能完成的全部平台能力，但仍受同一权限、校验和风险规则约束。

## 5. 统一函数与命令目录

平台能力以统一函数注册，例如：

- `novel.create`
- `outline.create_volume`
- `outline.create_chapter`
- `outline.reorder`
- `document.update`
- `character.create`
- `world_entry.update`
- `fact.approve`
- `chapter.generate`
- `asset.delete`

每个函数必须声明输入/输出 Schema、权限和适用范围、风险级别、幂等键、预览能力、差异生成方式、撤销策略及领域事件。

执行链路固定为：

```text
自然语言或页面动作
→ 选择统一函数
→ 参数、权限、revision 与幂等校验
→ 预览或执行
→ 单一应用事务提交
→ 返回结构化结果并发布事件
→ 人工确认、撤销或继续对话
```

## 6. 动态上下文

每次模型调用重新计算上下文，不持久化容易过期的固定滑动窗口。

- 必选锚点：作品核心、当前结构路径、当前章节规划、上一章承接内容、当前卷目标。
- 候选内容：邻近章节、相关人物、世界规则、地点、伏笔和研究资料。
- 稳定事实：仅限已审批事实。
- 临时资料：当前对话与本次任务输入。

选择流程：

```text
任务类型
→ 生成候选资料
→ 加入必选锚点
→ 按叙事距离、显式提及、审批状态和任务相关性排序
→ 按来源预算裁剪
→ 保存选中与未选中的理由
```

- 卷窗口以当前卷边界为基础，根据任务和 Token 预算动态扩展相邻章节。
- 首期使用结构关系、名称引用和章节距离，不引入向量 RAG；只有出现可复现召回失败后再评估。
- 相同输入、状态和预算必须得到确定的上下文选择结果。

## 7. 专用 Workflow

Workflow 是小说生产流程，不建设通用连接器市场。画布图是唯一执行真源；保存时编译为不可变版本，历史运行永久引用当时版本。

### 7.1 首期节点

- 开始与输入
- 上下文选择
- 提示词模板
- 模型调用
- 平台函数
- Python 纯计算
- 条件
- 有上限的循环
- 人工审批
- 输出

### 7.2 交互与执行

- React Flow 画布支持拖拽创建、类型化连线、框选、多选、复制粘贴、撤销重做、自动对齐和适配全图。
- 右侧属性面板编辑节点参数，并实时反映在节点摘要上。
- 画布是结构、坐标与连线的唯一编辑面，保存并重载后语义不变；提示词与 Python 等节点源码在节点编辑器中独立维护。
- Python 节点使用 CodeMirror，声明输入和 JSON 输出，只做纯计算，不能访问数据库或平台函数。
- 支持单节点试运行、从节点继续、完整运行、取消、失败重试、人工暂停和刷新/重启后恢复。
- 节点显示等待、运行、成功、失败和暂停；详情展示输入输出摘要、耗时、Token、错误和重试。
- Workflow 可保存、复制、发布版本并绑定到作品、卷、章节或任务。

交互目标参考百炼 Workflow、Langflow、Sim 和 React Flow，但不复制其庞大连接器体系。

## 8. 生成、审稿与审计

基础链路必须覆盖：新建作品 → 卷章与规划 → Agent 研究 → 人物与世界资料 → 稳定事实审批 → Workflow 选择 → 上下文预览 → 章节生成 → 运行详情 → 接受、修改或撤销。

每次运行详情展示：

- Workflow 名称和版本。
- 各节点状态、输入输出、耗时、重试和错误。
- 实际注入上下文、选择理由及未注入原因。
- Agent 工具调用和审批记录。
- 各模型输入、输出和 Token；只有配置价格时才计算费用。
- 最终正文、审查结果和写入操作。

- 流式生成必须记录模型、上下文快照、输入/输出 Token、耗时、错误和结果。
- 作者可以直接编辑正文，接受写入前后均可查看版本与差异。
- 未配置模型、生成失败、预算停止和节点失败必须给出可行动错误，不能伪装为成功。

## 9. 地图与媒体

- 地图库以 `MapProject` 和坐标化 `MapTile` 管理地图工程。
- 用户选择方向或空白区域扩展；后端组合相邻图块和重叠边缘作为 Outpaint 输入。
- 保存原图、生成结果、种子、提示词、模型和邻接关系，对重叠区羽化或泊松融合。
- 结果先预览，确认后进入正式地图；重新生成单块不得破坏已确认图块。
- 算法与交互参考 `stablediffusion-infinity`，不直接搬运其旧 Gradio/PyScript 界面和老模型实现。
- 首个云端适配器面向百炼画面扩展 API，同时保留 Stability AI 和本地 Diffusers Provider 接口；任何付费调用先获得主人批准。

## 10. 数据、安全与平台演进

- 继续采用 Python、FastAPI、SQLModel/Alembic 和本地 SQLite，按领域组织单体应用，不拆微服务。
- 每个写操作只有一次事务提交；任一步失败必须整体回滚。
- 幂等键重复提交不得产生重复章节、人物或工具结果；旧 revision 写入返回冲突。
- 图片和大文件通过存储适配器管理；本地落文件系统，云端可切对象存储。
- 新系统使用全新数据库；旧 SQLite、媒体和配置只归档，不读取、不迁移、不覆盖。
- 未来网站增加 PostgreSQL、对象存储、账户、客户数据和配额边界；桌面端优先用 Tauri 外壳复用同一前端，Python 后端作为 Sidecar。

## 11. 当前非目标

- 不拆微服务，不建设通用连接器市场。
- 首期不引入向量 RAG。
- Python Worker 首期是受限的本地可信执行环境，不宣称为安全沙箱。
- 不重写第二套桌面 UI。
- 不为了界面丰富而添加没有真实后端语义的按钮、筛选或数据大屏。

## 12. 第一次正式验收

必须从全新数据库完成：

1. 新建作品并打开。
2. 创建卷、章节和规划。
3. Agent 搜索资料并保留来源。
4. Agent 创建人物和世界设定，页面实时出现。
5. 创建并审批稳定事实。
6. 编辑并发布作品专用 Workflow。
7. 预览上下文并生成章节。
8. 查看每个节点、工具、上下文和 Token 明细。
9. 接受正文后关闭应用并重启，恢复相同作品、章节、标签页和运行记录。
10. 快速切换另一部作品，再返回启动页，验证状态不串联。
11. 触发高风险修改，验证差异、拒绝、批准和撤销。
12. 验证旧数据库及归档文件完全未被修改。

自动测试使用假模型。后端测试、前端行为测试、类型检查、构建、MCP 完整链路与真实浏览器截图是不同证据，缺一不可；任何真实模型、图片额度或付费 API 验收必须在调用前列出预计请求与成本并获得主人批准。
