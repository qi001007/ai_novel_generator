# AI 长篇小说工作台 PRD

版本：v1 收尾版（2026-09-09）

## 1. 产品定位

这是作者本人使用的单机写作工作台，不是多人 SaaS。它解决的核心问题不是“一次生成一章”，而是长篇写作中的上下文失忆、设定漂移、角色失控、伏笔断裂和人工核对成本。

产品原则：

- 作者始终拥有最终写入权；AI 可以读取、生成和提出改动，不能静默改规划。
- 规划、设定、正文、审稿和生成记录共同服务一条写作闭环，不拆成多个数据孤岛。
- 上下文必须可见、可调、受预算约束；不能悄悄丢资料。
- 先交付能持续写作的闭环，再增加高级编辑与视觉辅助。

## 2. 用户场景

- 管理多部作品，日常推进 1–3 章，每章约 2000–4000 字。
- 用 A/B/C/D 四层规划控制全书、目录、剧情弧和单章。
- 与 Agent 讨论剧情、查资料、查看改动提案，并由作者确认后执行。
- 生成正文后直接编辑、校验、审稿、终审、导出与恢复。
- 连续写作时追踪人物状态、伏笔与已确认事实。

## 3. v1 核心闭环

    新建作品
      → 编写 A/B/C/D 规划与设定
      → 对话要求生成目标章
      → 查看目标章与注入清单并确认
      → 流式生成正文
      → 机械校验 + AI 七维审稿
      → 人工编辑与终审
      → 摘要/事实记录
      → 导出或从快照恢复

v1 只有在主人能独立走完这条链时才算完成；测试全绿不能替代流程验收。

## 4. 功能需求

### 4.1 作品与章节

- 书架支持新建、编辑、打开和删除作品。
- 每部作品独立持有规划、设定、章节、对话、审稿和生成记录。
- 章节可显式追加、在指定章后插入、删除和重新编号；章号是位置，章名由 B 目录持有。
- 删除与批量改号前创建快照；恢复不得覆盖其他作品或用户后来修改的内容。
- 正文与简报必须按章配对，不能只创建其中一半。

### 4.2 四层规划

| 层 | 内容 | 作用 |
|---|---|---|
| A 全书蓝图 | 主线、主题、核心冲突、约束、终局 | 全书低频约束 |
| B 目录 | 章号、章名、剧情功能、备注 | 章节顺序与索引 |
| C 剧情弧 | 起止章、目标、冲突、收束、状态 | 中程连续性 |
| D 单章简报 | 本章目标、事件、视角、人物、事实、钩子 | 正文直接输入 |

- 四层规划与文本设定通过 Markdown 投影编辑，但数据库仍是唯一真源。
- 人工修改、AI 提案与新建简报复用同一文件写入口。
- AI 修改必须展示 diff；结构键、主键和 AI 白名单由后端校验。
- B 默认提供可搜索列表，也能切到源码视图；两种视图不得形成两份状态。

### 4.3 写作上下文

- 对话与正文生成共用 collect_items() 资料池，只允许排序策略不同。
- 默认预算 12000 字；清单展示每份资料的来源、字符数、档位、是否被裁及原因。
- 必给：作品与文风、A 蓝图、本章 D 简报、上一章简报与上一章完整正文。
- B 与 C 以目标章前后 20 章为窗口；B 只带章名、剧情功能和备注，不带其他章正文。
- 与本章直接相关的人物和伏笔优先；未匹配人物必须在清单中明示，不能静默消失。
- 世界观不整体强制注入；被简报或本章明确引用的设定优先，其余按相关度和预算选择。
- 除上一章外，不向正文生成注入其他章节全文。
- 主人指出某类资料缺失或多余时，只调整对应 collector 和排序测试。

### 4.4 正文与质量

- 按简报流式生成整章，记录任务、模型、输入/输出 token、耗时和注入摘要。
- 机械校验至少覆盖必要事实、禁用项和基础结构；规则必须在界面说明。
- AI 审稿覆盖一致性、角色行为、节奏、连贯、伏笔、钩子和文风，并引用正文证据。
- 作者能直接编辑正文；终审决定、章摘要和确认事实可追溯。
- 未配置模型、生成失败和预算停止必须给出可行动的错误，不能伪装成成功。

### 4.5 对话 Agent

- 支持自由对话、斜杠命令、@引用、文本附件、流式正文与独立推理显示。
- Agent 可以列文件、读文件、联网查证和多步调用；每步显示工具、耗时与返回规模。
- Agent 不拥有任意写工具。规划改动以提案呈现，作者点击应用后才写入。
- “生成第 N 章”以确认动作卡连接现有生成链：Agent 定位目标，作者确认，系统执行；取消或重复点击不得写入。
- 对话历史由数据库持有；框架不得建立第二份 session 或 memory 真源。

### 4.6 前端

- 书架进入三栏工作台：左侧规划/设定/对话导航，中间对话，右侧文件与正文编辑。
- 关键动作必须可达、可解释；未开放能力隐藏或禁用并说明原因，不出现假按钮。
- 深浅主题、字体和强调色是本机偏好；视觉细则与不可回退项只看 UI-DESIGN.md。
- 规划、设定、人物、调用详情、导出与恢复必须读取真实后端数据。

### 4.7 数据安全与可携带

- SQLite 是唯一持久化真源；Markdown 是投影与可导出格式。
- 作品、章节和文档支持快照恢复；快照数量有上限。
- 支持整书和单章导出为可带走的文本格式。
- 密钥只写不回显，不进入日志、导出或版本库。

## 5. v1 非目标

- 多用户、权限系统、公开发布平台和全自动批量成书。
- 向量 RAG、插件系统、DAG 工作流和磁盘双向同步。
- 自动级联改写 A/B/C/D；任何跨层改动都要作者确认。
- 生图、世界观地图完整交互、跨作品检索。
- 双栏对照、选区 Diff、内联审稿气泡、版本历史和 Token 聚合总账不阻塞 v1，可在真实使用后决定。

## 6. 验收

### 6.1 交付验收

- 在隔离作品连续完成至少 3 章的规划、对话触发生成、编辑、审稿、终审、导出和恢复。
- 每次生成的注入清单符合 §4.3，且没有未说明的裁剪。
- 破坏性动作可恢复；重复点击、刷新和失败重试不产生重复数据。
- 后端测试、前端测试、类型检查和构建全部通过；关键页面真机截图由主人审核。

### 6.2 产品价值验证

主人用真实作品连续推进 10 章后判断：

1. 至少 8 章不需要大幅重写；
2. 整理上下文与审稿的总时间低于纯手工流程；
3. 角色、设定或伏笔问题能在下一至两章内暴露；
4. 主人愿意继续用它写第 11 章。

## 7. 文档边界

本文不记录完成状态、代码路径、选型研究或提交历史。当前进度看 WORKSTREAM-PLAN.md；实现结构看 ARCHITECTURE.md；决策理由与已废方案看 DECISIONS.md；界面规格看 UI-DESIGN.md。
