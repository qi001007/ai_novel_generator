### 1 切换钮被 tab 挤出可视区 → 必须钉死在条的右端

`.file-tabs-actions`（渲染／源码切换）现在是 `.file-tabs` 这个**滚动容器里的最后一个子元素**，
所以 tab 一多它就跟着滚走了——主人：「我得滚鼠标滚很后面才能出现它，你这个东西应该是固定在这儿的」。

- 做法：把这一组按钮**移出滚动容器**，做成标签条的固定右端（`.file-tabs` 外层再包一层
  flex：左边 `overflow-x:auto` 的滚动区 + 右边不滚的操作区），或 `position: sticky; right: 0`
  并给一个不透明底。**不接受**「留在滚动区里靠 margin-left:auto」。
- 验收（写进 `uiInvariants.test.ts`）：开 8 个 tab、把条滚到最左，操作钮的
  `getBoundingClientRect().right` 仍等于条的右内边界，且 `left > 条左`（可见）。

2. 除此之外其他部分应有正常的被挤压感。

### 4 悬停才现的横向滑块又没了（主人这次是真的火了）

主人：「我之前让你弄的那个东西，你之前弄得很好的，现在也不见了。**你说你又找回来了，

- 经过：第十轮他要「滚动条改隐藏式（悬停才出现）」→ 我做了 `scrollbar-width: none` +
  `:hover{thin}`；第十二批他又抱怨悬停时滑块占 10px 把 40px 的条压成 30px；
  第十三批我**把滑块整个删了**——他要么没说要删，要的是**两个都要**。
- 正解（唯一同时满足「悬停可见 + 不占布局」的做法）：**自绘覆盖式滑块**——

- 复用：`.file-tabs` 与 `.editor-tabs` 共用一个组件/hook，别各写一份。
- 验收：条溢出时悬停能看到并拖动滑块；同时 tab 高度恒 39px、条恒 40px（两个都要）。

## 六、取证脚本（每轮 UI 改动后跑一遍，别靠目测）

放在 `.scratch/`，已验证可用的入口：

- `cdp.mjs` → `connect(url)` 返回 `{ evaluate, click, clickPoint, send, shot, close }`；
  无 Chrome，用裸 Edge + CDP（端口 9333）。
- **写 CDP 脚本一律 `-Encoding utf8`**。用 `ascii` 会把脚本里的中文静默变成 `?`，
  于是 `find(n => n.getAttribute("aria-label") === "展开调用记录")` 永远匹配不上，
  报出来的「控件不存在」全是脚本 bug——本会话被它误导三次。
- **命中区审计（已写）**：`node .scratch/hit-area-audit.mjs [url] [open-file]`。
  它**不信 CSS 盒子**——上一轮就是盒子骗的我（`.tree-prefix` 写着 28px，实际被 overflow
  裁掉）——而是用 `elementFromPoint` 从控件中心向四向走，量「真点得到」的范围，
  伪元素覆盖层和负 margin 都算进去。三段输出：`small`（命中 < 24px）、
  `clipped`（命中框任何一部分落在最近滚动/裁切容器之外）、
  `unreachable`（中心被别的东西盖住）。改完任何一处控件尺寸都跑一遍。
- **对比度审计**：逐元素算合成背景与前景的 WCAG 比值（浅色主题曾一次抓出 13 处不过 AA，
  其中十处共用同一个 `--text-2`）。
- **量「主人看到的线」的正确方法**：给定一条视觉接缝，枚举 `elementFromPoint` 沿途
  以及两侧容器**所有子元素**的 `left/right/backgroundColor`，不要只查你怀疑的那个元素有没有 border。
