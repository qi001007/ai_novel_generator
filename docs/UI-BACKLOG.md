### 19.1 ✅ 上传附件按钮不能用，且要以 chip 形式呈现附件（批注 1）

- 主人：「上传文件按钮现在不能用。我希望它呈现附件的形式，如图所示」，参考图是一枚
  `× 🐱 AGENTS.md` 形状的 chip。
- 现状取证：`ChatPane.tsx:1092-1100` 的回形针是 `disabled` + `title="附件上传暂未开放"`。
  那是上一轮我按「假控件比没控件糟」主动关掉的——因为旧实现把选中的文件放进 state
  却没有任何请求读它。**主人现在要的是它真的能用**，不是它诚实。
- 判据：
  1. 点回形针可选文件；选中后在输入框上方出现 chip（`× + 图标 + 文件名`），点 `×` 移除；
  2. 发送后附件内容**真的进模型输入**：作为 `ContextItem(kind="附件", ref="attachment:<名>")`
     追加进 `prepare_turn` 里那**同一批** `items`，仍由 `render_context()` 渲染、
     仍记进 `context_refs`。**不许开第二条注入通路**（红线 D-04 / D-06）；
  3. 可观测：注入清单与「资料」区能看到这条附件（不是只存在请求里）；
  4. 边界：只收文本类（md/txt/json/yaml/csv/log/py/…），单个与总量各有上限，
     非文本或超限**给原因**（不静默丢、也不静默截半）；
  5. 发送成功后 chip 清空——上一版的病是 chip 活过了发送；
  6. 测试：后端「带附件的 turn，items 末尾有附件项且 context_refs 记到」；
     前端「渲染 chip／× 移除／发送后清空」。

  · 后端：`prepare_turn(..., attachments=)` 把附件变成 `ContextBlock(kind="附件",

    **一条注入通路都没多**（D-04 / D-06 守住）。`attachment_blocks()` 是边界：

## 四、取证脚本（每轮 UI 改动后跑一遍，别靠目测）

放在 `.scratch/`，已验证可用的入口：

- `cdp.mjs` → `connect(url)` 返回 `{ evaluate, click, clickPoint, send, shot, close }`；
  无 Chrome，用裸 Edge + CDP（端口 9333）。
- **写 CDP 脚本一律 `-Encoding utf8`**。用 `ascii` 会把脚本里的中文静默变成 `?`，
  于是 `find(n => n.getAttribute("aria-label") === "展开调用记录")` 永远匹配不上，
  报出来的「控件不存在」全是脚本 bug——本会话被它误导三次。
- **命中区审计（已写）**：`node .scratch/hit-area-audit.mjs [url] [open-file]`。
  它**不信 CSS 盒子**——上一轮就是盒子骗的我（`.tree-prefix` 写着 28px，实际被 overflow
  裁掉）——而是用 `elementFromPoint` 从控件中心向四向走，量「真点得到」的范围，
  伪元素覆盖层和负 margin 都算进去。三段输出：`small`（命中 < 24px）、
  `clipped`（命中框任何一部分落在最近滚动/裁切容器之外）、
  `unreachable`（中心被别的东西盖住）。改完任何一处控件尺寸都跑一遍。
- **对比度审计**：逐元素算合成背景与前景的 WCAG 比值（浅色主题曾一次抓出 13 处不过 AA，
  其中十处共用同一个 `--text-2`）。
- **量「主人看到的线」的正确方法**：给定一条视觉接缝，枚举 `elementFromPoint` 沿途
  以及两侧容器**所有子元素**的 `left/right/backgroundColor`，不要只查你怀疑的那个元素有没有 border。
