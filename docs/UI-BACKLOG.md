### 16.9 ✅ 拖分栏关掉一栏后，同一次手势里拖回来应当重新打开（批注 9）

- 真因（已读码）：`applyPane` 一关闭就 `return true`，`onMove` 立刻 `stopDrag()`——
  指针还没抬起，手势已经结束，之后往回拖没有任何人接收，只能去点顶栏图标。
- 判据：一次 `pointerdown … pointerup` 之内来回拖，栏**可关可开**，不必松手重来；
  方向键同理（往回按能回来）；关闭仍**幂等**（同方向连按不得反复开关——
  上一轮第 12 次 ArrowRight 把刚关的栏开回来就是这条）；关掉的栏宽度回到静止最小值而非 90px。
- **已做（2026-09-05 真机按住鼠标来回拖过）**。真因一句话：`applyPane` 一关就 `return true`，
  `onMove` 于是立刻 `stopDrag()`——**手指还在按钮上，手势却已经结束了**。
  改成 `applyPane` 不返回值、只有 `pointerup` 结束手势；同一条规则加上反向：
  回到地板之上就 `reopenPane`。指针与方向键共用这一个判据。
  **两处非显然的坑，都是量出来/测出来的**：
  ① 拖拽期间所有 `onMove` 共用同一个闭包，`hidden` 是**旧渲染快照**——
     「它是不是已经关了」不能从闭包里读。加 `hiddenRef` 镜像 + 写入一律走
     `setHidden((prev) => …)` 函数式更新，同帧两次 move 不会互相抵消；
  ② `closePane` 会把存量宽度**复位到静止最小值**（这是「图标叫回来不是 90px 细条」那条
     判据要的），于是方向键若拿它当基准，**同方向再按一次就像「变宽了」而把刚关的栏开回来**
     ——正是第十五批钉过的那个病换了个方向复发。改成：栏已隐藏时以 `CLOSE_AT - 1` 为基准，
     于是只有「反方向」能重开。指针不需要这个修正（它从抓取点量位移）。
  真机（1656 宽，按住不放）：
  对话栏边界右拖 1020px → 正文栏关闭、轨道 `44 300 1 1311`；**不松手**左拖 → 轨道回到
  `44 300 1 814 1 496`，`resizing` 始终 true；结构栏边界左拖 500px → 关闭、顶栏图标
  `aria-pressed=false`；不松手右拖 → 260px 回来、图标 true。
  新增 2 条测试（反向可重开 + 同方向仍幂等），前端 132 → **134 passed / 18 files**。

## 六、取证脚本（每轮 UI 改动后跑一遍，别靠目测）

放在 `.scratch/`，已验证可用的入口：

- `cdp.mjs` → `connect(url)` 返回 `{ evaluate, click, clickPoint, send, shot, close }`；
  无 Chrome，用裸 Edge + CDP（端口 9333）。
- **写 CDP 脚本一律 `-Encoding utf8`**。用 `ascii` 会把脚本里的中文静默变成 `?`，
  于是 `find(n => n.getAttribute("aria-label") === "展开调用记录")` 永远匹配不上，
  报出来的「控件不存在」全是脚本 bug——本会话被它误导三次。
- **命中区审计（已写）**：`node .scratch/hit-area-audit.mjs [url] [open-file]`。
  它**不信 CSS 盒子**——上一轮就是盒子骗的我（`.tree-prefix` 写着 28px，实际被 overflow
  裁掉）——而是用 `elementFromPoint` 从控件中心向四向走，量「真点得到」的范围，
  伪元素覆盖层和负 margin 都算进去。三段输出：`small`（命中 < 24px）、
  `clipped`（命中框任何一部分落在最近滚动/裁切容器之外）、
  `unreachable`（中心被别的东西盖住）。改完任何一处控件尺寸都跑一遍。
- **对比度审计**：逐元素算合成背景与前景的 WCAG 比值（浅色主题曾一次抓出 13 处不过 AA，
  其中十处共用同一个 `--text-2`）。
- **量「主人看到的线」的正确方法**：给定一条视觉接缝，枚举 `elementFromPoint` 沿途
  以及两侧容器**所有子元素**的 `left/right/backgroundColor`，不要只查你怀疑的那个元素有没有 border。
