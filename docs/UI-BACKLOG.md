### 32.5 提案与列表随 token 逐字增长（32.4 剩下的那一半）

- [ ] 判据：一次 B 层生成里，目录的行随模型产出逐条长出来，主人能在流还没结束时看到已定下的行；最快也要小于「该步完成」那一刻。
- [ ] 现状：32.4 已把「等收尾那句客套话打完字」摘掉，卡跟着那一步到；但那一步内部仍是整块产出——`propose_toc` 的 `payload` 得完整才过得了 D-38 那道校验，所以列表最快只能按步到齐。
- [ ] 代价说在前面：要逐 token 增长，要么让半截 JSON 也能渲染成行（增量解析），要么在流里加一种新的部分提案事件——两条都会撞上 D-38「只给合法卡」与 D-40「只有一条提案通道」的边界。本轮不做，等主人点头。

### 35.19 工具参数面不对称：`read_file` 收顶层字段，`propose_*` 只收一个 `payload` 串

- [ ] 假网关实测（`.scratch/stub-gateway.py`，端口 8123）：`{"name": "read_file", "arguments": {"path": "arcs.md"}}` 直接可用；而 `propose_*` 必须把整份动作 JSON 塞进**单个字符串字段** `payload`，把 `chapters` 平铺给 `propose_toc` 拿到的是 `_compile() got an unexpected keyword argument 'chapters'`——模型看见的是拒绝，不是正确写法。
- [ ] 本轮只登记，未改（工作规则 2）。要裁的是「统一成顶层字段」还是「在拒绝文案里把该工具的完整写法逐字递回去」：前者动工具表 schema，后者只动一句文案。

验收：同一类误用在假网关重放，返回的文案能点出该工具的真实参数形状（或该次调用直接被接住）；两类工具的参数面在 `docs/` 里有一处写明，不再靠模型试出来。
